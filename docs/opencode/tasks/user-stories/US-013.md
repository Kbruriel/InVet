# US-013 — Centro de notificaciones internas y correo MVP

## Historia de usuario

- US-013-01 (Propietario): Como **propietario**, quiero **ver un centro de notificaciones que muestre alertas sobre citas, consultas, recetas y pagos** para estar al tanto de la actividad de mi clinica.
- US-013-02 (Staff/clínico): Como **staff o clínico**, quiero **marcar notificaciones como leidas y ver un badge con el conteo de no leidas** para priorizar tareas pendientes.
- US-013-03 (Visitante/Anonimo): Como **usuario anonimo**, quiero **ser redirigido al login** sin exponer datos de notificaciones de otros tenants.

## Criterios de aceptación

- AC-013-01: El receptor ve endpoint paginado GET /api/v1/notifications con items y meta {page, page_size, total, pages}.
- AC-013-02: Al recibir un evento se crea una fila de Notification unica por receptor; constraint unico (user_id, event_type, ref_type, ref_id).
- AC-013-03: POST /notifications/{id}/read marca is_read=true; el usuario no puede marcar notificaciones ajenas (404).
- AC-013-04: POST /notifications/read-all marca todas como leidas y devuelve count actualizado.
- AC-013-05: GET /notifications/unread-count devuelve conteo entero filtrado por receptor y clinic_id del token.
- AC-013-06: Sin bearer valido → 401 en los cuatro endpoints privados.
- AC-013-07: El frontend muestra NotificationCenter con tabs Todas/No leidas, paginacion visual y EmptyState sin datos.
- AC-013-08: Badge en el header nav muestra conteo > 0 entre parentesis o badge rojo; oculto si count == 0.
- AC-013-09: Migracion a013 notificaciones reversible con tabla y constraint unico por receptor y evento.
- AC-013-10: El puerto abstracto EmailProvider se implementa con LoggingEmailSender que loguea recipient/subject/provider sin enviar correos reales ni exponer secretos.
- AC-013-11: Duplicado de emision no crea fila extra; constraint unico previene insert (no raise).
- AC-013-12: IDOR/BOLA verificado en listado, conteo y marcacion por receptor y tenant.

## Alcance del slice

- Cinco tipos de evento MVP mapeados a notificacion con subject/body descriptivo.
- Puerto abstracto EmailProvider con implementacion stub para MVP.
- Endpoint paginado, marcacion individual y en bloque, conteo no leidas todos protegidos por receptor y tenant.
- Ruta /portal/notifications con los cinco estados UX (loading, empty, success, error, submitting).
- Badge de no leidas integrado en el header nav del portal.
- Pruebas pytest para backend (happy, negative, auth, idor, dedup) y Jest + Playwright para frontend.

## Fuera de alcance

- Integration real con SMTP o servidor de correo externo (solo logueo).
- Notificaciones push ni websockets ni polling periodico.
- Plantillas avanzadas o multidioma para correos.
- Archivar o retener notificaciones mas alla de MVP.
- Modulos de productos, marketplace, carrito, checkout, facturacion.
