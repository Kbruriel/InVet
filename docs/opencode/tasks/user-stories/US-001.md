## Titulo

Base tecnica y design system

## Descripcion funcional

Preparar la base verificable del monolito backend, frontend Next.js y reglas visuales compartidas. Esta historia constituye el cimiento sobre el cual los slices siguientes (auth, landing, perfil de clinica, administracion, propietarios/mascotas, citas, consulta medica, recetas, pagos, ratings, notificaciones, soporte, reportes, administracion inicial y hardening) deben reutilizar contratos, estructura y componentes.

## Usuarios/roles involucrados

- **Desarrollador/Implementador**: necesita un repositorio inicial con reglas claras de estructura, seguridad, rutas y diseño visual.
- **QA**: necesita comandos reproducibles para validar arranque, healthcheck, configuracion, autenticacion minima y estados UI basico desde el dia uno.

## Criterios de aceptacion

| ID | Criterio | Capa | Medible por |
|---|---|---|---|
| AC-001-01 | Backend expone raiz (`GET /`), healthcheck (`GET /health`) y API versionada (`GET /api/v1/`). | BE | `pytest app/tests/test_main.py -q` |
| AC-001-02 | Configuracion centralizada disponible por entorno (proyecto, prefijo DB, secretos). | BE | `pytest app/tests/test_main.py -q`; inspeccion de settings |
| AC-001-03 | Seguridad minima: passwords con hash seguro, JWT emitido/validado, rutas protegidas rechazan acceso anonimo. | BE | `pytest app/tests/api/test_auth_api.py -q` |
| AC-001-04 | Persistencia base preparada para autenticacion (DB inicializa en pruebas). | BE | `pytest app/tests/test_database.py -q` |
| AC-001-05 | Frontend base renderiza shell publico sin CDN critica dependiente. | FE | `npm run build`; inspeccion de layout |
| AC-001-06 | Cliente API centraliza consumo de backend con URL configurable. | FE | `npm run typecheck` |
| AC-001-07 | Estados comunes (loading, error, empty) existen como componentes compartidos. | FE/ UIA | pruebas de componentes |
| AC-001-08 | QA ejecuta happy path, negative path y permisos con evidencia trazable. | QA | `docs/opencode/qa/QA-001-results.md` |
