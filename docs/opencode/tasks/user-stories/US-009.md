# US-009 — Consulta médica básica / Basic medical consultation

## Historia de usuario

Como **veterinario de una clínica registrada**,
quiero **registrar una consulta médica vinculada a una cita completada**,
para que pueda **documentar diagnóstico, historia clínica y recomendaciones** de forma segura y trazable sin salir del portal clínico.

## Criterios de aceptación (derivados de AC-009-01 a AC-009-14)

### Como veterinario — Registrar consulta (AC-009-01, AC-009-02, AC-009-07, AC-009-10, AC-009-11)
1. Navigo a `/clinic/appointments/[id]/consultation` para una cita con `status=completed` y registro la consulta con `diagnosis` requerido, `history` y `recommendations` opcionales (AC-009-01).
2. Si intento registrar una consulta para una cita que no está `completed`, el sistema me devuelve un error claro (422) sin crear registro parcial (AC-009-02).
3. El formulario valida los campos requeridos en el cliente y el backend valida con schemas Pydantic; campos ausentes producen 422 con mensaje legible (AC-009-07, AC-009-10).
4. Si pertenezco a otra clínica que la de la cita, el registro falla con 403 sin exponer datos ajenos (AC-009-11).
5. Si la cita ya tiene una consulta registrada, el sistema me indica que existe (409) en lugar de duplicarla (AC-009-06).

### Como propietario — Consultar historial y detalle (AC-009-03, AC-009-04, AC-009-05, AC-009-13)
6. Navego a `/portal/owner/pets/[id]/consultations` y veo el historial de consultas de mi mascota en read-only, paginado (AC-009-03, AC-009-09).
7. Navego a `/portal/owner/consultations/[id]` y visualizo el detalle de una consulta con etiquetas legibles para no-médicos, sin botones de edición (AC-009-04).
8. Solo veo consultas de mis mascotas; nunca de otros propietarios (AC-009-05).
9. Si mi mascota no tiene consultas, veo un estado empty con texto descriptivo (AC-009-13).

### Como sistema — Seguridad, consistencia y persistencia (AC-009-08, AC-009-12, AC-009-14)
10. Formulario y listados muestran estados UI consistentes: loading, submitting, success, error, empty (AC-009-08, AC-009-09).
11. Un usuario no autenticado recibe 401 en todos los endpoints de `/consultations` (AC-009-12).
12. La migración Alembic crea la tabla `consultations` con unique sobre `appointment_id` y es reversible sin perder datos (AC-009-14).

## Dependencias de la historia
- BE-008: `Appointment` con `status` que incluye `completed`.
- BE-007: `Pet` con FK a `owner_id`.
- BE-002/BE-006: Roles de usuario (propietario, clinica, veterinario).
- BE-005: Tablas `clinics` y `branches` existentes para FK.

## Fuera de alcance de esta historia
- Actualización o eliminación de consultas (PUT/PATCH/DELETE) — slice futuro si aplica.
- Adjuntos/archivos clínicos (imágenes, PDFs).
- Historial clínico completo integrado con otros registros.
- Notificaciones por consulta nueva.
- Reportes estadísticos ni dashboard clínico.
