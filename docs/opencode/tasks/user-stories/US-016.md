# US-016 — Administracion inicial del sistema

## Historia de usuario principal

**Como** administrator global del sistema ("system admin")
**Quiero** gestionar usuarios internos, clinicas, configuraciones legales (terminos/privacidad), reportes globales y tickets de soporte basico
**Para** operar la administracion central desde un panel unico sin depender de cada clinica individual.

## Historias derivadas

### US-016-H01 — Gestion global de usuarios internos

**Como** admin global
**Quiero** listar, crear y desactivar usuarios internos entre todas las clinicas
**Para** tener control total del personal registrado en el sistema.

#### Criterios de aceptacion

| ID | Descripcion | Fuente |
| --- | --- | --- |
| AC-016-01 | El admin crea un usuario interno con email, rol y nombre validos; el endpoint `POST /api/v1/admin/internal-users` retorna 201 y el usuario es persistido en DB. | BE + FE |
| AC-016-02 | El admin desactiva un usuario activo via `PATCH /api/v1/admin/internal-users/{id}/deactivate`; el usuario ya no puede autenticar. | BE + QA |
| AC-016-03 | El admin obtiene una lista paginada de todos los usuarios internos de todas las clinicas via `GET /api/v1/admin/internal-users`. | BE + FE |
| AC-016-04 | El admin puede consultar el detalle de un usuario especifico via `GET /api/v1/admin/internal-users/{id}`. | BE |

### US-016-H02 — Gestion global de clinicas

**Como** admin global
**Quiero** crear y listar clinicas registradas en el sistema
**Para** verificar y controlar que clinicas operan en la plataforma InVet.

#### Criterios de aceptacion

| ID | Descripcion | Fuente |
| --- | --- | --- |
| AC-016-05 | El admin crea una nueva clinica con nombre y direccion validos via `POST /api/v1/admin/clinics`; se persiste correctamente en DB y retorna 201. | BE + FE |
| AC-016-06 | El admin visualiza el listado paginado de todas las clinicas registradas via `GET /api/v1/admin/clinics`. | BE + QA |

### US-016-H03 — Edicion de terminos y politica de privacidad

**Como** admin global
**Quiero** editar y publicar terminos de servicio y politica de privacidad del sistema
**Para** mantener la documentacion legal actualizada y disponible publicamente.

#### Criterios de aceptacion

| ID | Descripcion | Fuente |
| --- | --- | --- |
| AC-016-07 | Cualquier usuario (aun sin autenticar) puede leer los terminos publicados via `GET /api/v1/terms` (retorna 200). | BE + FE + QA |
| AC-016-08 | Cualquier usuario (aun sin autenticar) puede leer la politica de privacidad via `GET /api/v1/privacy` (retorna 200). | BE + FE + QA |
| AC-016-09 | Solo usuarios con rol "system_admin" pueden guardar cambios en terminos/privacidad via `PUT`; cualquier otro rol o usuario anonimo recibe 403 Forbidden. | BE + QA |
| AC-016-10 | Los cambios editados en terminos/privacidad se reflejan inmediatamente en las respuestas GET posteriores. | BE |

### US-016-H04 — Reportes operativos globales agregados

**Como** admin global
**Quiero** consultar reportes agregados (citas, servicios, mascotas, consultas, calificaciones, pagos) por periodo a nivel de todas las clinicas
**Para** tomar decisiones de negocio con vista integral del sistema.

#### Criterios de aceptacion

| ID | Descripcion | Fuente |
| --- | --- | --- |
| AC-016-11 | El endpoint `GET /api/v1/admin/reports/{tipo}` retorna datos agregados cross-clinic filtrados por `period_start` y `period_end` para el admin global. | BE + QA |
| AC-016-12 | Usuarios con rol distinto a "system_admin" no pueden acccesar los reportes globales (retornan 403). | BE + QA |

### US-016-H05 — Gestion de tickets de soporte basico

**Como** admin global (o admin asignado)
**Quiero** ver y actualizar el estado de los tickets de soporte desde todas las clinicas
**Para** dar seguimiento centralizado a incidencias reportadas por usuarios.

#### Criterios de aceptacion

| ID | Descripcion | Fuente |
| --- | --- | --- |
| AC-016-13 | El admin global puede listar tickets de soporte paginados de todas las clinicas via `GET /api/v1/admin/support-tickets`. | BE + FE |
| AC-016-14 | El admin puede actualizar el estado de un ticket (ej: open -> resolved) via `PUT /api/v1/admin/support-tickets/{id}` y el cambio persiste en DB. | BE + QA |
