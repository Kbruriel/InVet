# US-004 - Perfil público de clínica/sucursal

## Historia de usuario

**Como** visitante/anónimo o propietario registrado,  
**Quiero** ver el perfil público de una clínica o sucursal con servicios, horarios, calificaciones y disponibilidad,  
**Para** tomar una decisión informada sobre solicitar una cita.

## Criterios de aceptación

### AC-004-01 - Perfil público sin autenticación
- **Dado** que un usuario visita la ruta `/clinics/[id]` sin autenticación  
- **Cuando** la sucursal existe y es publica  
- **Entonces** se muestra el perfil con servicios, horarios, rating summary y disponibilidad  
- **Y** no se exponen datos sensibles (contraseñas, notas internas, IDs de usuarios)

### AC-004-02 - Perfil protegido con validación
- **Dado** que un usuario autenticado visita `/clinics/[clinicId]/branches/[branchId]`  
- **Cuando** el usuario tiene acceso a la clínica/sucursal  
- **Entonces** se muestra el perfil completo con datos adicionales de acceso  
- **Y** si no tiene acceso, se devuelve 403 sin datos

### AC-004-03 - Servicios de la sucursal
- **Dado** que una sucursal existe  
- **Cuando** se consulta `/clinics/branches/{id}/services`  
- **Entonces** se devuelve la lista de servicios con nombre, precio base y estado activo/inactivo

### AC-004-04 - Horarios disponibles
- **Dado** que una sucursal tiene horarios configurados  
- **Cuando** se consulta `/clinics/branches/{id}/schedules?date=YYYY-MM-DD`  
- **Entonces** se devuelve la lista de horarios disponibles para esa fecha

### AC-004-05 - Resumen de calificaciones
- **Dado** que una sucursal tiene calificaciones  
- **Cuando** se consulta `/clinics/branches/{id}/rating-summary`  
- **Entonces** se devuelve promedio, conteo y distribución sin datos personales

### AC-004-06 - Disponibilidad básica
- **Dado** que una sucursal tiene cupos configurados  
- **Cuando** se consulta `/clinics/branches/{id}/availability`  
- **Entonces** se devuelve el estado actual de disponibilidad

### AC-004-07 - CTA de solicitud de cita
- **Dado** que un usuario ve el perfil público  
- **Cuando** hace clic en el CTA "Solicitar cita"  
- **Entonces** navega al flujo de citas con el branch_id correcto

### AC-004-08 - IDs inexistentes devuelven error seguro
- **Dado** que un usuario solicita una sucursal inexistente  
- **Cuando** hace GET a `/clinics/branches/{invalid_id}`  
- **Entonces** se devuelve 404 con mensaje genérico sin información interna

### AC-004-09 - Permisos cruzados fallan
- **Dado** que un usuario de una clínica intenta acceder a otra  
- **Cuando** hace GET al endpoint protegido con clinic_id diferente  
- **Entonces** se devuelve 403 sin datos devueltos

## Dependencias

- BE-002 (autenticación) cerrado — modelos de usuario/rol existentes
- BE-003 (landing pública) cerrado — patrones de búsqueda reutilizables
- FE-002 (formularios auth) — componentes de sesión reutilizables

## Fuera de alcance

- Creación de citas (BE-008)
- Gestión de propietarios/mascotas (BE-007)
- Pagos y checkout (BE-011)
- Notificaciones (BE-013)
- Reportes administrativos (BE-015)

## Notas de implementación

- Los DTOs deben excluir todos los campos sensibles.
- El CTA de cita debe ser un enlace simple al flujo de BE-008.
- No se requiere autenticación para el perfil público.
- La UI debe manejar estados: loading, error, empty, success.
