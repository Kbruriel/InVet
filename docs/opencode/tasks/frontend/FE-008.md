# FE-008 — Solicitud y gestión de citas

## Objetivo

Solicitud desde perfil, agenda propietario y agenda clínica.

## Dependencias

- Backend relacionado: `BE-008`.
- QA relacionado: `QA-008`.
- Tokens y reglas visuales en `docs/opencode/references/frontend_visual_alignment.md`.

## Rutas canónicas de implementación

- Frontend base: `http://localhost:3000`
- UI del propietario: `frontend/src/app/portal/owner/appointments/page.tsx`
- UI de alta de cita: `frontend/src/app/portal/owner/appointments/new/page.tsx`
- UI de detalle del propietario: `frontend/src/app/portal/owner/appointments/[id]/page.tsx`
- UI de agenda clínica: `frontend/src/app/clinic/appointments/page.tsx`
- UI de detalle clínico: `frontend/src/app/clinic/appointments/[id]/page.tsx`
- Cliente de citas: `frontend/src/features/appointments/api.ts`
- API de referencia: `http://localhost:8000/api/v1/appointments`

## Comandos que el agente FE debe reconocer

- Cargar el entorno completo para navegar la UI real:

  ```text
  docker compose up -d --build --force-recreate db backend frontend
  ```

- Validación UI formal del slice:

  ```text
  /run-ui-checks FE-008
  ```

- La regresión UI y Playwright deben ejecutarse sobre `http://localhost:3000`; la evidencia no debe apuntar al backend directo para simular navegación de navegador.

- Cuando haga falta verificar la infraestructura antes de la UI, la referencia de base sigue siendo `http://localhost:3000` y el cliente API debe consumir `http://localhost:8000/api/v1/appointments`.

## Alcance MVP

- Implementar UI y consumo API del slice `008`.
- Mantener arquitectura Next.js/TypeScript/React/Tailwind.
- Reutilizar componentes desde `src/shared/ui`.
- Centralizar API en `src/shared/api`.
- Manejar loading, error, empty, success y submitting.
