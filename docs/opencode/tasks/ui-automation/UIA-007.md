# UIA-007 — Pruebas de UI Automation para Propietarios y Mascotas

## Objetivo

Automatizar la validacion del portal propietario en navegador, cubriendo flujos de perfil, mascotas e historial basico con cobertura multi-navegador.

## Cobertura de navegadores

- Chromium (principal)
- Firefox (compatibilidad)
- WebKit opcional si el pipeline lo soporta

## Rutas a cubrir

| Ruta | Descripcion | Estados a verificar |
| --- | --- | --- |
| `/portal/owner` | Portal principal del propietario | loading, success, empty |
| `/portal/owner/edit` | Edicion de perfil | submitting, success, error |
| `/portal/owner/pets/new` | Registro de nueva mascota | submitting, success, error validacion |
| `/portal/owner/pets/{pet_id}` | Detalle de mascota con historial | loading, success, empty (sin historial) |

## Flujos a automatizar

### Flujo 1: Verificar portal propietario logueado

```
1. Navegar a /login
2. Autenticar con credenciales de propietario valido
3. Redirigir a /portal/owner
4. Verificar que se muestra el nombre del propietario
5. Verificar que el listado de mascotas muestra estado empty o success
6. Verificar que no hay errores en la consola del navegador
```

### Flujo 2: Registrar nueva mascota

```
1. En /portal/owner, hacer clic en "Agregar mascota"
2. Redirigir a /portal/owner/pets/new
3. Completar formulario con datos validos (nombre, especie, raza, edad)
4. Hacer clic en "Guardar"
5. Verificar respuesta 201 simulada o redireccion a detalle de mascota
6. Verificar mensaje de exito
7. Verificar que la mascota aparece en el listado
```

### Flujo 3: Validar formulario con datos invalidos

```
1. En /portal/owner/pets/new, dejar campos requeridos vacios
2. Hacer clic en "Guardar"
3. Verificar que se muestran errores de validacion en la UI
4. Verificar que no se envia peticion al backend (no network request)
```

### Flujo 4: Actualizar perfil de propietario

```
1. En /portal/owner, hacer clic en "Editar perfil"
2. Redirigir a /portal/owner/edit
3. Modificar campo telefono
4. Hacer clic en "Guardar"
5. Verificar respuesta 200 simulada
6. Verificar mensaje de exito
7. Verificar que el dato actualizado se refleja en la UI
```

### Flujo 5: Eliminar mascota

```
1. En /portal/owner, seleccionar una mascota del listado
2. Hacer clic en "Eliminar"
3. Confirmar eliminacion en dialog/modal
4. Verificar respuesta 204 simulada
5. Verificar que la mascota desaparece del listado
6. Verificar mensaje de exito
```

### Flujo 6: Historial basico de mascota

```
1. En /portal/owner/pets/{pet_id}, navegar a seccion de historial
2. Si hay consultas previas, verificar que se muestran en lista
3. Si no hay consultas, verificar estado empty apropiado
4. Verificar que el loading state aparece durante la carga
```

## Estados UX a verificar

| Estado | Donde aplicar | Como verificar |
| --- | --- | --- |
| loading | Todas las rutas al cargar datos | Spinner visible, contenido deshabilitado |
| submitting | Formularios al enviar | Boton disabled, spinner en boton |
| success | Despues de operacion exitosa | Mensaje de confirmacion, datos actualizados |
| error | En fallo de peticion o validacion | Banner de error, mensaje legible |
| empty | Listado sin mascotas | Mensaje "No tienes mascotas registradas" |

## Responsive a verificar

| Breakpoint | Ancho minimo | Que verificar |
| --- | --- | --- |
| Mobile | 320px | Formulario en columna, botones touch-friendly |
| Tablet | 768px | Layout adaptativo, espaciado adecuado |
| Desktop | 1024px+ | Dos columnas donde aplique, tabla con scroll horizontal si es necesario |

## Criterios de salida

- Todos los flujos pasan en Chromium.
- Flujos criticos (login, portal, registrar mascota) pasan en Firefox.
- No hay errores de consola en los flujos exitosos.
- Estados UX visibles y correctos en todos los escenarios.
- Layout responsive sin desbordes en mobile/tablet/desktop.
