# UIA-006 — Servicios, veterinarios y usuarios internos

## Objetivo

Plan de cobertura de automatizacion de navegador (Playwright) para las vistas admin de servicios, veterinarios y usuarios internos del slice 006.

## Alcance

- Navegacion a rutas admin protegidas.
- Listados paginados con filtros.
- Formularios de creacion y edicion con validacion.
- Estados UX: loading, error, empty, success.
- Permisos visibles: acciones ocultas/deshabilitadas segun rol.
- Responsive en mobile y desktop.

## Fuera de alcance

- Pruebas de backend directo (cubiertas por QA-006).
- Pruebas de API HTTP sin navegador (cubiertas por APIA-006).
- Pruebas de rendimiento o carga.

## Casos de prueba UI

### TC-UIA-006-01: Listado de servicios con paginacion
- **Dado** un usuario admin autenticado con servicios existentes
- **Cuando** navego a `/admin/services`
- **Entonces** veo una tabla con datos, controles de paginacion visibles y metadatos de paginacion
- **Criterios**: AC-006-03, AC-006-10

### TC-UIA-006-02: Listado de servicios vacio
- **Dado** un usuario admin autenticado sin servicios
- **Cuando** navego a `/admin/services`
- **Entonces** veo mensaje "No hay servicios" o equivalente en estado empty
- **Criterios**: AC-006-28

### TC-UIA-006-03: Crear servicio con datos validos
- **Dado** un usuario admin autenticado en `/admin/services/create`
- **Cuando** completo el formulario con nombre, precio y duracion validos y submit
- **Entonces** veo estado de success y redireccion al listado con el nuevo servicio
- **Criterios**: AC-006-01

### TC-UIA-006-04: Crear servicio con datos invalidos
- **Dado** un usuario admin autenticado en `/admin/services/create`
- **Cuando** intento submit con campos vacios o precios negativos
- **Entonces** veo errores de validacion por campo sin detalles internos del servidor
- **Criterios**: AC-006-09, AC-006-29

### TC-UIA-006-05: Editar servicio existente
- **Dado** un usuario admin autenticado con un servicio existente
- **Cuando** navego a `/admin/services/[id]/edit`, modifico datos y submit
- **Entonces** veo estado de success y los cambios persisten en el listado
- **Criterios**: AC-006-02

### TC-UIA-006-06: Desactivar servicio
- **Dado** un usuario admin autenticado en el listado de servicios
- **Cuando** ejecuto la accion desactivar en un servicio
- **Entonces** el servicio desaparece del listado activo y aparece si filtro por inactivos
- **Criterios**: AC-006-04, AC-006-11

### TC-UIA-006-07: Listado de veterinarios con paginacion
- **Dado** un usuario admin autenticado con veterinarios existentes
- **Cuando** navego a `/admin/veterinarians`
- **Entonces** veo una tabla con datos, controles de paginacion visibles y metadatos de paginacion
- **Criterios**: AC-006-09, AC-006-10

### TC-UIA-006-08: Crear veterinario con datos validos
- **Dado** un usuario admin autenticado en `/admin/veterinarians/create`
- **Cuando** completo el formulario con nombre, licencia y especialidad validos y submit
- **Entonces** veo estado de success y redireccion al listado con el nuevo veterinario
- **Criterios**: AC-006-07

### TC-UIA-006-09: Crear veterinario con licencia duplicada
- **Dado** un usuario admin autenticado en `/admin/veterinarians/create`
- **Cuando** intento crear con una licencia ya existente en la clinica
- **Entonces** veo error de validacion indicando conflicto (409)
- **Criterios**: AC-006-09

### TC-UIA-006-10: Listado de usuarios internos con paginacion
- **Dado** un usuario admin autenticado con usuarios internos existentes
- **Cuando** navego a `/admin/internal-users`
- **Entonces** veo una tabla con datos, controles de paginacion visibles y metadatos de paginacion
- **Criterios**: AC-006-15, AC-006-10

### TC-UIA-006-11: Crear usuario interno con datos validos
- **Dado** un usuario admin autenticado en `/admin/internal-users/create`
- **Cuando** completo el formulario con user_id valido, nombre y rol, y submit
- **Entonces** veo estado de success y redireccion al listado con el nuevo usuario interno
- **Criterios**: AC-006-13

### TC-UIA-006-12: Crear usuario interno con user_id invalido
- **Dado** un usuario admin autenticado en `/admin/internal-users/create`
- **Cuando** intento crear con un user_id que no existe en el sistema de auth
- **Entonces** veo error de validacion indicando que el usuario no existe (404 o 400)
- **Criterios**: AC-006-09

### TC-UIA-006-13: Asignar servicio a veterinario desde UI
- **Dado** un usuario admin autenticado en el perfil de un veterinario
- **Cuando** selecciono un servicio de la misma clinica y confirmo asignacion
- **Entonces** veo estado de success y la asociacion aparece en el listado de servicios del veterinario
- **Criterios**: AC-006-19

### TC-UIA-006-14: Desasignar servicio de veterinario desde UI
- **Dado** un usuario admin autenticado con una asignacion activa
- **Cuando** ejecuto la accion desasignar en el perfil del veterinario
- **Entonces** la asociacion desaparece y el veterinario ya no aparece en listados de ese servicio
- **Criterios**: AC-006-21

### TC-UIA-006-15: Permisos visibles - rol insuficiente
- **Dado** un usuario con rol viewer (no admin/manager) autenticado
- **Cuando** navego a `/admin/services` o cualquier ruta admin
- **Entonces** los botones de crear/editar/eliminar estan ocultos o deshabilitados
- **Criterios**: AC-006-12, AC-006-30

### TC-UIA-006-16: Acceso no autenticado a rutas admin
- **Dado** un usuario no autenticado
- **Cuando** intento navegar a `/admin/services` o cualquier ruta admin
- **Entonces** soy redirigido a login y recibo 401 al intentar consumir la API
- **Criterios**: AC-006-06

### TC-UIA-006-17: Responsive - mobile (375px)
- **Dado** un usuario admin autenticado en cualquier vista admin
- **Cuando** redimensiono el viewport a 375px de ancho
- **Entonces** la tabla se transforma en vista de tarjetas y los formularios apilan campos verticalmente sin perdida de funcionalidad
- **Criterios**: AC-006-31

### TC-UIA-006-18: Responsive - desktop (1440px)
- **Dado** un usuario admin autenticado en cualquier vista admin
- **Cuando** redimensiono el viewport a 1440px de ancho
- **Entonces** la tabla se muestra completa con todas las columnas y los formularios usan layout de dos columnas cuando aplica
- **Criterios**: AC-006-31

### TC-UIA-006-19: Estados de carga en listados
- **Dado** un usuario admin autenticado
- **Cuando** navego a cualquier vista admin y la API tarda en responder
- **Entonces** veo un spinner o skeleton mientras se cargan los datos
- **Criterios**: AC-006-27

### TC-UIA-006-20: Estados de error HTTP
- **Dado** un usuario admin autenticado
- **Cuando** la API responde con 500 en un listado o formulario
- **Entonces** veo un mensaje de error generico sin exponer detalles internos del servidor
- **Criterios**: AC-006-29

## Estrategia tecnica

- Framework: Playwright (TypeScript) existente en `InVet_UI_Automation/`.
- Configuracion: `playwright.config.ts` con baseURL apuntando al frontend local o Docker.
- Autenticacion: Crear usuario admin de prueba via API antes de cada suite, usar session cookie/token para las pruebas UI.
- Selectores: data-testid en componentes clave (tablas, formularios, botones) para estabilidad.
- Screenshots: Capturar en cada caso de error y en estados empty/loading.
- Viewports: Probar al menos 375px (mobile), 768px (tablet) y 1440px (desktop).

- Screenshots de cada estado UX (loading, error, empty, success) en al menos una vista.
