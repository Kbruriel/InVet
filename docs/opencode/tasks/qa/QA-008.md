# QA-008 — Solicitud y gestión de citas

## Objetivo

Validar flujo de cita extremo a extremo.

## Dependencias

- Backend relacionado: `BE-008`.
- Frontend relacionado: `FE-008`.

## Entorno y rutas de validacion

- Frontend base para UI y regresion: `http://localhost:3000`
- Backend base para API y checks HTTP: `http://localhost:8000`
- API base del slice: `http://localhost:8000/api/v1`
- UI a validar: `http://localhost:3000/clinicas`, `http://localhost:3000/portal/owner/appointments`, `http://localhost:3000/portal/owner/appointments/new`, `http://localhost:3000/clinic/appointments`
- API a validar: `/api/v1/clinicas` y `/api/v1/appointments`
- Si el stack no esta arriba, levantarlo con `docker compose up -d --build --force-recreate db backend frontend`

## Comandos que el agente QA debe reconocer

- Cargar el stack completo antes de validar:

  ```text
  docker compose up -d --build --force-recreate db backend frontend
  ```

- Validar la UI del slice antes del cierre:

  ```text
  /run-ui-checks FE-008
  ```

- Validar backend y evidencia técnica del slice:

  ```text
  /run-checks BE-008
  ```

- Si el flujo requiere DB real, la corrida de backend debe usar `docker compose up -d db` y luego `docker compose run --rm backend pytest ...` o el equivalente documentado.

- Toda evidencia debe nombrar explícitamente `http://localhost:3000`, `http://localhost:8000`, `/api/v1/clinicas`, `/api/v1/appointments` y las rutas frontend que se validaron.

## Alcance de validación

- Happy path.
- Negative path.
- Permisos por rol.
- Ownership/tenant/branch cuando aplique.
- IDOR/BOLA.
- Estados HTTP.
- Estados UI.
- Responsive.
- Regresión del flujo principal.

## Casos mínimos

1. Usuario autorizado ejecuta flujo correctamente.
2. Usuario no autenticado recibe 401 cuando aplica.
3. Usuario autenticado sin permiso recibe 403 cuando aplica.
4. Acceso cruzado por ID ajeno falla de forma segura.
5. Input inválido produce error claro sin filtrar detalles internos.
6. UI muestra loading/error/empty/success.
7. Listados aplican paginación o límites si corresponde.

## Evidencia requerida

- Comandos ejecutados.
- Resultados esperados vs obtenidos.
- Captura textual o resumen de UI.
- Defectos con pasos de reproducción.
- Riesgo residual si aplica.

## Definition of Done

- [ ] Happy path validado.
- [ ] Negative path validado.
- [ ] Permisos validados.
- [ ] IDOR/BOLA validado si aplica.
- [ ] Regresión mínima validada.
- [ ] Evidencia documentada.
