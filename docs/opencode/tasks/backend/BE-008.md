# BE-008 — Solicitud y gestión de citas

## Objetivo

Crear/solicitar/confirmar/cancelar/reprogramar/no-show/completar citas.

## Dependencias

- BE-007, FE-007, QA-007 cerrados.
- Revisar matriz en `docs/opencode/02_be_fe_qa_task_matrix.md`.
- Frontend relacionado: `FE-008`.
- QA relacionado: `QA-008`.

## Rutas y archivos canónicos

- Backend base de ejecucion: `http://localhost:8000`
- API base del slice: `http://localhost:8000/api/v1`
- Router canónico: `backend/app/api/v1/routers/appointment_router.py`
- Schemas canónicos: `backend/app/api/v1/schemas/appointment_schemas.py`
- Endpoints del slice: `/api/v1/appointments`
- Frontend de referencia para validar el flujo end-to-end: `http://localhost:3000`
- UI de citas del propietario: `http://localhost:3000/portal/owner/appointments`
- UI de alta de cita: `http://localhost:3000/portal/owner/appointments/new`
- UI de agenda clínica: `http://localhost:3000/clinic/appointments`

## Comandos que el agente BE debe reconocer

- Levantar el stack completo para validar el slice:

  ```text
  docker compose up -d --build --force-recreate db backend frontend
  ```

- Levantar solo la base de datos cuando la corrida lo permita:

  ```text
  docker compose up -d db
  ```

- Ejecutar pruebas backend dentro del contenedor cuando el slice necesita DB real:

  ```text
  docker compose run --rm backend pytest app/tests/test_appointment_use_cases.py -q
  docker compose run --rm backend pytest app/tests/api/test_appointments_api.py -q
  ```

- Reutilizar el contenedor ya levantado cuando el runtime esté sano:

  ```text
  docker compose exec backend pytest app/tests/ -q
  ```

- Cierre técnico asociado al slice:

  ```text
  /run-checks BE-008
  /update-docs BE-008
  ```

Los endpoints de implementación deben quedar en `backend/app/api/v1/routers/appointment_router.py` y los schemas canónicos en `backend/app/api/v1/schemas/appointment_schemas.py`.

## Alcance MVP

- Implementar únicamente capacidades necesarias para el slice `008`.
- Exponer contratos bajo `/api/v1`.
- Mantener separación API/Application/Domain/Infrastructure/Core.
- Agregar pruebas automatizadas aplicables.

## Fuera de alcance

- Productos, marketplace, carrito, checkout, pasarela de pago de servicios, facturación electrónica y timbrado fiscal.
- Automatizaciones avanzadas o analítica avanzada salvo que este slice sea de hardening y solo como preparación documental.

## Actividades Backend

1. Revisar entidades y reglas existentes.
2. Crear o ajustar entidades/value objects de dominio.
3. Crear casos de uso en application.
4. Crear interfaces de repositorio/ports.
5. Implementar repositorios SQLAlchemy en infrastructure.
6. Crear schemas Pydantic separados por contexto en `backend/app/api/v1/schemas/appointment_schemas.py`.
7. Crear/ajustar routers FastAPI en `backend/app/api/v1/routers/appointment_router.py`.
8. Crear migraciones Alembic si aplica.
9. Agregar pruebas Pytest/HTTPX.
10. Validar permisos, ownership e IDOR/BOLA cuando aplique.

## Criterios de aceptación

- El contrato requerido por `FE-008` existe o queda documentado como mock temporal aprobado.
- Los routers no contienen lógica de negocio.
- No se exponen modelos ORM.
- Las respuestas son paginadas cuando hay listados.
- Los errores son consistentes y no filtran información interna.
- Las pruebas cubren al menos happy path y un negative path.
