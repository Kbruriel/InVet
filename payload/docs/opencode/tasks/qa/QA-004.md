# QA-004 - Public clinic/branch profile

## Objective

Validate public data exposure, permission handling, and safe error behavior.

## Scope

- Test creation or adjustment when needed.
- Test execution when the environment allows it.
- Happy path.
- Negative path.
- Role-based permission checks.
- Ownership/tenant/branch validation when applicable.
- IDOR/BOLA.
- HTTP status codes.
- UI states.

## Minimum cases

1. Authorized user executes the flow successfully.
2. Unauthenticated user receives `401` when the route requires auth.
3. Authenticated user without access receives `403` when the route requires auth.
4. Cross-tenant or foreign-id access fails safely.
5. Invalid input returns a clear error without leaking internals.

## Expected BE-004 contract

- `GET /api/v1/clinics/branches/{branch_id}` is public and does not require auth.
- `GET /api/v1/clinics/{clinic_id}/{branch_id}` is protected and requires auth plus access control.
